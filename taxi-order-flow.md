# Поток заказа такси

Полный жизненный цикл заказа: от ввода адреса до оплаты и оценки поездки.

## Основной сценарий

```mermaid
sequenceDiagram
    autonumber
    actor P as Пассажир
    participant App as Мобильное приложение
    participant API as Order Service
    participant Geo as Geo & Pricing
    participant Disp as Dispatch (подбор водителя)
    participant D as Приложение водителя
    participant Pay as Платёжный сервис
    participant Push as Push-уведомления

    Note over P,Geo: Фаза 1. Расчёт поездки

    P->>App: вводит адрес назначения
    App->>Geo: GET /suggest?query=...
    Geo-->>App: подсказки адресов
    P->>App: выбирает адрес и тариф
    App->>Geo: POST /price (откуда, куда, тариф)
    Geo-->>App: маршрут, ETA, цена (с учётом спроса)
    App-->>P: показывает цену и время подачи

    Note over P,Pay: Фаза 2. Создание заказа

    P->>App: подтверждает заказ
    App->>API: POST /orders
    API->>Pay: холдирование суммы на карте
    Pay-->>API: hold_id, статус OK
    API-->>App: 201 Created, order_id, статус SEARCHING

    Note over API,D: Фаза 3. Подбор водителя

    API->>Disp: найти водителя (гео, тариф, рейтинг)

    loop по кандидатам, пока никто не принял
        Disp->>D: предложение заказа (таймаут 15 сек)
        alt водитель принял
            D-->>Disp: accept
        else отказ или таймаут
            D-->>Disp: reject / timeout
            Note right of Disp: переход к следующему кандидату
        end
    end

    alt водитель найден
        Disp-->>API: driver_id, ETA подачи
        API->>API: статус ASSIGNED
        API->>Push: «Водитель найден»
        Push-->>P: уведомление
    else свободных водителей нет
        Disp-->>API: no_drivers_available
        API->>Pay: отмена холда
        API->>Push: «Не удалось найти машину»
        Push-->>P: уведомление
    end

    Note over P,D: Фаза 4. Подача и поездка

    loop каждые 3–5 сек, пока идёт заказ
        D->>API: координаты водителя
        API-->>App: позиция машины на карте
    end

    D->>API: прибыл на точку (статус ARRIVED)
    API->>Push: «Машина подана»
    Push-->>P: уведомление
    P->>D: садится в машину
    D->>API: начал поездку (статус IN_RIDE)
    D->>API: завершил поездку (статус COMPLETED)

    Note over API,P: Фаза 5. Оплата и завершение

    API->>Geo: пересчёт по факту (пробки, ожидание, изменение маршрута)
    Geo-->>API: итоговая сумма
    API->>Pay: списание с холда

    alt оплата прошла
        Pay-->>API: payment_id, успех
        API-->>App: чек и итоговая сумма
    else отказ банка
        Pay-->>API: ошибка оплаты
        API->>API: статус PAYMENT_FAILED, долг на пассажире
        API-->>App: просьба привязать другую карту
    end

    App-->>P: экран оценки поездки
    P->>App: ставит оценку водителю
    App->>API: POST /orders/{id}/rating
```

## Альтернативный сценарий: отмена заказа

```mermaid
sequenceDiagram
    autonumber
    actor P as Пассажир
    participant App as Мобильное приложение
    participant API as Order Service
    participant Disp as Dispatch
    participant D as Приложение водителя
    participant Pay as Платёжный сервис

    P->>App: нажимает «Отменить»
    App->>API: DELETE /orders/{id}

    alt водитель ещё не назначен
        API->>Disp: остановить подбор
        API->>Pay: отмена холда
        API-->>App: 200 OK, статус CANCELLED, без комиссии
    else водитель уже едет, прошло менее N минут
        API->>D: заказ отменён
        API->>Pay: отмена холда
        API-->>App: 200 OK, статус CANCELLED, без комиссии
    else водитель ждёт на точке дольше бесплатного ожидания
        API->>D: заказ отменён
        API->>Pay: списание платы за отмену
        API-->>App: 200 OK, статус CANCELLED, удержана комиссия
    end
```

## Статусы заказа

| Статус | Когда наступает |
| --- | --- |
| `SEARCHING` | заказ создан, идёт подбор водителя |
| `ASSIGNED` | водитель принял заказ и едет на точку |
| `ARRIVED` | водитель на месте подачи |
| `IN_RIDE` | пассажир в машине, поездка идёт |
| `COMPLETED` | поездка завершена, идёт расчёт |
| `PAID` | оплата прошла успешно |
| `PAYMENT_FAILED` | списание не прошло, зафиксирован долг |
| `CANCELLED` | заказ отменён пассажиром, водителем или системой |

## Ключевые решения в схеме

- **Холдирование до подбора водителя.** Сумма блокируется сразу после создания заказа — так система отсеивает неплатёжеспособных пассажиров до того, как отправит к ним машину. Итоговое списание идёт с холда после поездки.
- **Подбор — отдельный сервис.** Dispatch перебирает кандидатов в цикле с таймаутом на ответ, поэтому отказ одного водителя не роняет заказ.
- **Цена пересчитывается дважды.** Предварительная — до подтверждения, фактическая — после завершения: маршрут и время в пути меняются.
- **Трекинг вынесен в отдельный поток.** Координаты идут потоком (WebSocket или частый polling), а не в рамках основного запроса заказа.
