# User stories и критерии приёмки

Роли:

- **Разработчик клиентского приложения** делает фан-приложение или виджет для медиа. Главный потребитель API.
- **Аналитик** выгружает результаты для статистики и моделей, в том числе для беттинг-аналитики.

Критерии приёмки записаны в Gherkin, чтобы их можно было автоматизировать как контрактные тесты. Коды ошибок и поля — из [openapi.yaml](openapi.yaml).

## US-01. Расписание предстоящих матчей

**Как** разработчик клиентского приложения, **я хочу** получать список предстоящих матчей, **чтобы** показывать пользователям расписание.

API: `GET /matches?status=upcoming`

```gherkin
Функция: Расписание матчей

  Сценарий: Только предстоящие матчи
    Дано в системе 3 матча в статусе "upcoming" и 5 в статусе "finished"
    Когда клиент запрашивает GET /matches?status=upcoming
    Тогда ответ имеет код 200
    И в items только матчи со статусом "upcoming"
    И total равен 3

  Сценарий: Неизвестный статус
    Когда клиент запрашивает GET /matches?status=cancelled
    Тогда ответ имеет код 400
    И code в теле ответа равен "INVALID_PARAMETER"
```

Порядок сортировки пока не зафиксирован, см. [Q-2](README.md#открытые-вопросы).

## US-02. Постраничная загрузка

**Как** разработчик клиентского приложения, **я хочу** получать матчи порциями, **чтобы** быстро показать первую страницу и подгружать остальные по запросу.

API: `GET /matches?limit=&offset=`. Почему именно так — в [ADR-0002](adr/0002-offset-pagination.md).

```gherkin
Функция: Пагинация списка матчей

  Предыстория:
    Дано в системе 137 матчей

  Сценарий: Размер страницы по умолчанию
    Когда клиент запрашивает GET /matches
    Тогда в items 20 матчей
    И total равен 137

  Сценарий: Последняя неполная страница
    Когда клиент запрашивает GET /matches?limit=50&offset=100
    Тогда в items 37 матчей

  Сценарий: Смещение за пределами выборки
    Когда клиент запрашивает GET /matches?offset=500
    Тогда ответ имеет код 200
    И items пустой
    И total равен 137

  Структура сценария: Недопустимый limit
    Когда клиент запрашивает GET /matches?limit=<limit>
    Тогда ответ имеет код 400
    И code в теле ответа равен "INVALID_PARAMETER"

    Примеры:
      | limit |
      | 0     |
      | 101   |
      | -5    |
```

## US-03. Матчи турнира

**Как** аналитик, **я хочу** получить все матчи одного турнира, **чтобы** считать статистику по событию.

API: `GET /matches?eventId=`

```gherkin
Функция: Фильтр по турниру

  Сценарий: Матчи одного турнира
    Дано турнир "iem-cologne-2026" с 24 матчами
    Когда клиент запрашивает GET /matches?eventId=iem-cologne-2026&limit=100
    Тогда в items 24 матча
    И у всех матчей eventName равен "IEM Cologne 2026"

  Сценарий: Турнир без матчей
    Когда клиент запрашивает GET /matches?eventId=unknown-event
    Тогда ответ имеет код 200
    И items пустой
    И total равен 0
```

Слабое место: клиенту неоткуда узнать `eventId`, см. [Q-1](README.md#открытые-вопросы).

## US-04. Детали матча

**Как** разработчик клиентского приложения, **я хочу** получить матч со счётом по картам, **чтобы** показать результат серии.

API: `GET /matches/{matchId}`. Поток запроса — в [match-flow.md](match-flow.md).

```gherkin
Функция: Детали матча

  Сценарий: Завершённый матч
    Дано завершённый матч "m-2026-0731-01" в формате bo3
    Когда клиент запрашивает GET /matches/m-2026-0731-01
    Тогда ответ имеет код 200
    И в teams две команды в порядке team1, team2
    И в maps от 2 до 3 карт со счётом roundsTeam1 и roundsTeam2

  Сценарий: Матч ещё не начался
    Дано матч "m-2026-0801-02" в статусе "upcoming"
    Когда клиент запрашивает GET /matches/m-2026-0801-02
    Тогда ответ имеет код 200
    И maps пустой

  Сценарий: Матч не найден
    Когда клиент запрашивает GET /matches/m-unknown
    Тогда ответ имеет код 404
    И тело ответа содержит code и message
```

## US-05. Live-счёт

**Как** разработчик медиа-виджета, **я хочу** видеть идущие матчи и их текущий счёт, **чтобы** показывать live-результаты.

API: `GET /matches?status=live`, затем `GET /matches/{matchId}`. Правила статусов — в [match-lifecycle.md](match-lifecycle.md).

```gherkin
Функция: Live-матчи

  Сценарий: Счёт обновляется во время карты
    Дано матч "m-2026-0731-01" в статусе "live", на первой карте счёт 5:3
    Когда провайдер присылает событие: раунд выиграла команда team1
    И через 10 секунд клиент запрашивает GET /matches/m-2026-0731-01
    Тогда у первой карты roundsTeam1 равен 6 и roundsTeam2 равен 3

  Сценарий: Матч завершается
    Дано матч в формате bo3 в статусе "live", team1 выиграла первую карту
    Когда team1 выигрывает вторую карту
    Тогда статус матча становится "finished"
```

Пока по ответу нельзя понять, какая карта идёт прямо сейчас, см. [Q-3](README.md#открытые-вопросы).

## US-06. Рейтинг на момент матча

**Как** аналитик, **я хочу** видеть рейтинг команд на момент матча, **чтобы** находить апсеты и оценивать форму.

API: `Team.worldRanking` в `GET /matches/{matchId}`. Решение — в [ADR-0003](adr/0003-ranking-snapshot.md).

```gherkin
Функция: Рейтинг команды на момент матча

  Сценарий: Рейтинг не меняется после матча
    Дано команда "t-navi" была 4-й в рейтинге, когда начался матч "m-2026-0731-01"
    И после матча команда поднялась на 2-е место
    Когда клиент запрашивает GET /matches/m-2026-0731-01
    Тогда worldRanking команды "t-navi" равен 4

  Сценарий: Предстоящий матч показывает текущий рейтинг
    Дано матч "m-2026-0801-02" в статусе "upcoming" с участием "t-navi"
    И сейчас "t-navi" на 2-м месте в рейтинге
    Когда клиент запрашивает GET /matches/m-2026-0801-02
    Тогда worldRanking команды "t-navi" равен 2
```
