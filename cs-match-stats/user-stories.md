# User stories и критерии приёмки

Роли:

- **Разработчик клиентского приложения** делает фан-приложение или виджет для медиа. Главный потребитель API.
- **Аналитик** выгружает результаты для статистики и моделей, в том числе для беттинг-аналитики.

Критерии приёмки записаны в Gherkin, чтобы их можно было автоматизировать как контрактные тесты. Коды ошибок и поля — из [openapi.yaml](openapi.yaml), версия 1.1.

## US-01. Расписание предстоящих матчей

**Как** разработчик клиентского приложения, **я хочу** получать список предстоящих матчей, ближайшие первыми, **чтобы** показывать пользователям расписание.

API: `GET /matches?status=upcoming&sort=startsAt`. Почему сортировка задаётся явно — в [ADR-0005](adr/0005-explicit-sort.md).

```gherkin
Функция: Расписание матчей

  Сценарий: Только предстоящие матчи
    Дано в системе 3 матча в статусе "upcoming" и 5 в статусе "finished"
    Когда клиент запрашивает GET /matches?status=upcoming
    Тогда ответ имеет код 200
    И в items только матчи со статусом "upcoming"
    И total равен 3

  Сценарий: Ближайшие матчи первыми
    Дано предстоящие матчи начинаются 2026-10-03, 2026-10-01 и 2026-10-02
    Когда клиент запрашивает GET /matches?status=upcoming&sort=startsAt
    Тогда матчи в items идут по startsAt: 2026-10-01, 2026-10-02, 2026-10-03

  Сценарий: Одинаковое время начала
    Дано матчи "m-b" и "m-a" начинаются в одно время
    Когда клиент запрашивает GET /matches?sort=startsAt
    Тогда "m-a" идёт раньше "m-b"

  Сценарий: Неизвестный статус
    Когда клиент запрашивает GET /matches?status=postponed
    Тогда ответ имеет код 400
    И code в теле ответа равен "INVALID_PARAMETER"
```

## US-02. Постраничная загрузка

**Как** разработчик клиентского приложения, **я хочу** получать матчи порциями, **чтобы** быстро показать первую страницу и подгружать остальные по запросу.

API: `GET /matches?limit=&offset=`. Почему именно так — в [ADR-0002](adr/0002-offset-pagination.md).

```gherkin
Функция: Пагинация списка матчей

  Предыстория:
    Дано в системе 137 матчей

  Сценарий: Размер страницы и порядок по умолчанию
    Когда клиент запрашивает GET /matches
    Тогда в items 20 матчей
    И total равен 137
    И матчи идут от поздних к ранним по startsAt

  Сценарий: Последняя неполная страница
    Когда клиент запрашивает GET /matches?limit=50&offset=100
    Тогда в items 37 матчей

  Сценарий: Смещение за пределами выборки
    Когда клиент запрашивает GET /matches?offset=500
    Тогда ответ имеет код 200
    И items пустой
    И total равен 137

  Структура сценария: Недопустимые параметры
    Когда клиент запрашивает GET /matches?<параметр>
    Тогда ответ имеет код 400
    И code в теле ответа равен "INVALID_PARAMETER"

    Примеры:
      | параметр     |
      | limit=0      |
      | limit=101    |
      | offset=-5    |
      | sort=name    |
```

## US-03. Матчи турнира

**Как** аналитик, **я хочу** получить все матчи одного турнира, **чтобы** считать статистику по событию.

API: `GET /matches?eventId=`. Идентификатор турнира берётся из справочника ([US-07](#us-07-справочник-турниров)) или из поля `eventId` любого матча.

```gherkin
Функция: Фильтр по турниру

  Сценарий: Матчи одного турнира
    Дано турнир "iem-cologne-2026" с 24 матчами
    Когда клиент запрашивает GET /matches?eventId=iem-cologne-2026&limit=100
    Тогда в items 24 матча
    И у всех матчей eventId равен "iem-cologne-2026" и eventName равен "IEM Cologne 2026"

  Сценарий: Турнир без матчей
    Когда клиент запрашивает GET /matches?eventId=unknown-event
    Тогда ответ имеет код 200
    И items пустой
    И total равен 0
```

## US-04. Детали матча

**Как** разработчик клиентского приложения, **я хочу** получить матч со счётом по картам, **чтобы** показать результат серии.

API: `GET /matches/{matchId}`. Поток запроса — в [match-flow.md](match-flow.md).

```gherkin
Функция: Детали матча

  Сценарий: Завершённый матч
    Дано матч "m-2026-0731-01" в формате bo3, "t-navi" выиграла его 2:1
    Когда клиент запрашивает GET /matches/m-2026-0731-01
    Тогда ответ имеет код 200
    И в teams две команды в порядке team1, team2
    И в maps 3 карты со статусом "finished" и счётом roundsTeam1 и roundsTeam2
    И winnerTeamId равен "t-navi"
    И forfeit равен false

  Сценарий: Матч ещё не начался
    Дано матч "m-2026-0801-02" в статусе "upcoming"
    Когда клиент запрашивает GET /matches/m-2026-0801-02
    Тогда ответ имеет код 200
    И maps пустой
    И winnerTeamId не передаётся

  Сценарий: Матч не найден
    Когда клиент запрашивает GET /matches/m-unknown
    Тогда ответ имеет код 404
    И тело ответа содержит code и message
```

## US-05. Live-счёт

**Как** разработчик медиа-виджета, **я хочу** видеть идущие матчи и их текущий счёт, **чтобы** показывать live-результаты.

API: `GET /matches?status=live`, затем `GET /matches/{matchId}`. Правила статусов — в [match-lifecycle.md](match-lifecycle.md).

```gherkin
Функция: Live-матчи

  Сценарий: Видно, какая карта идёт сейчас
    Дано матч "m-2026-0731-01" в статусе "live", первая карта сыграна, идёт вторая
    Когда клиент запрашивает GET /matches/m-2026-0731-01
    Тогда у первой карты status равен "finished"
    И у второй карты status равен "live"

  Сценарий: Счёт обновляется во время карты
    Дано матч "m-2026-0731-01" в статусе "live", на текущей карте счёт 5:3
    Когда провайдер присылает событие: раунд выиграла команда team1
    И через 10 секунд клиент запрашивает GET /matches/m-2026-0731-01
    Тогда у текущей карты roundsTeam1 равен 6 и roundsTeam2 равен 3

  Сценарий: Матч завершается
    Дано матч в формате bo3 в статусе "live", team1 выиграла первую карту
    Когда team1 выигрывает вторую карту
    Тогда статус матча становится "finished"
    И winnerTeamId равен идентификатору team1
```

## US-06. Рейтинг на момент матча

**Как** аналитик, **я хочу** видеть рейтинг команд на момент матча, **чтобы** находить апсеты и оценивать форму.

API: `Team.worldRanking` в `GET /matches/{matchId}`. Решение — в [ADR-0003](adr/0003-ranking-snapshot.md).

```gherkin
Функция: Рейтинг команды на момент матча

  Сценарий: Рейтинг не меняется после матча
    Дано команда "t-navi" была 4-й в рейтинге, когда начался матч "m-2026-0731-01"
    И после матча команда поднялась на 2-е место
    Когда клиент запрашивает GET /matches/m-2026-0731-01
    Тогда worldRanking команды "t-navi" равен 4

  Сценарий: Предстоящий матч показывает текущий рейтинг
    Дано матч "m-2026-0801-02" в статусе "upcoming" с участием "t-navi"
    И сейчас "t-navi" на 2-м месте в рейтинге
    Когда клиент запрашивает GET /matches/m-2026-0801-02
    Тогда worldRanking команды "t-navi" равен 2
```

## US-07. Справочник турниров

**Как** аналитик, **я хочу** получить список турниров с их идентификаторами, **чтобы** выгружать матчи нужного турнира.

API: `GET /events`. Появился в v1.1.

```gherkin
Функция: Справочник турниров

  Сценарий: Новые турниры первыми
    Дано турниры "IEM Cologne 2026" с 2026-07-21 и "PGL Astana 2026" с 2026-05-10
    Когда клиент запрашивает GET /events
    Тогда ответ имеет код 200
    И первым в items идёт турнир с id "iem-cologne-2026"
    И у каждого турнира есть id и name

  Сценарий: Идентификатор из справочника работает в фильтре матчей
    Дано в GET /events есть турнир с id "iem-cologne-2026"
    Когда клиент запрашивает GET /matches?eventId=iem-cologne-2026
    Тогда в items только матчи этого турнира

  Сценарий: Недопустимый limit
    Когда клиент запрашивает GET /events?limit=101
    Тогда ответ имеет код 400
    И code в теле ответа равен "INVALID_PARAMETER"
```

## US-08. Отменённые матчи и технические поражения

**Как** разработчик клиентского приложения, **я хочу** видеть, что матч отменён или завершён техническим поражением, **чтобы** не показывать его как предстоящий и правильно показать победителя.

API: `Match.status`, `winnerTeamId`, `forfeit`. Решение и переходный период — в [ADR-0004](adr/0004-cancelled-and-forfeit.md).

```gherkin
Функция: Нестандартные исходы матча

  Сценарий: Техническое поражение до старта
    Дано команда team2 не явилась на матч "m-2026-0802-03"
    И организатор присудил техническую победу команде "t-navi"
    Когда клиент запрашивает GET /matches/m-2026-0802-03
    Тогда status равен "finished"
    И forfeit равен true
    И winnerTeamId равен "t-navi"
    И maps пустой

  Сценарий: Отменённый матч после переходного периода
    Дано сегодня 2026-10-24 или позже
    И матч "m-2026-1025-01" отменён организатором
    Когда клиент запрашивает GET /matches/m-2026-1025-01
    Тогда status равен "cancelled"
    И winnerTeamId не передаётся

  Сценарий: Отменённый матч во время переходного периода
    Дано сегодня раньше 2026-10-24
    И матч "m-2026-1001-01" отменён организатором
    Когда клиент запрашивает GET /matches
    Тогда матча "m-2026-1001-01" нет в items
```
