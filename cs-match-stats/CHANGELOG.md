# История изменений CS Match Stats API

Версии — по [семантическому версионированию](https://semver.org/lang/ru/): внутри `/v1` только обратно совместимые изменения ([ADR-0001](adr/0001-rest-contract-first.md)).

## 1.1.0 — 2026-09-24

Закрывает вопросы Q-1…Q-4, найденные при разборе v1.0 ([README](README.md#вопросы-к-контракту)).

### Добавлено

- `GET /events` — справочник турниров с пагинацией (Q-1).
- `Match.eventId` — идентификатор турнира для фильтра `eventId` (Q-1).
- Параметр `sort` в `GET /matches`: `startsAt` или `-startsAt`, по умолчанию `-startsAt` (Q-2, [ADR-0005](adr/0005-explicit-sort.md)).
- `MapResult.status` — `live` или `finished`: видно, какая карта идёт сейчас (Q-3).
- `Match.winnerTeamId` и `Match.forfeit` — победитель и признак технического поражения (Q-4, [ADR-0004](adr/0004-cancelled-and-forfeit.md)).
- Статус матча `cancelled` (Q-4). **Появляется в ответах не раньше 2026-10-24.**

### Изменено

- Порядок `GET /matches` зафиксирован: по `startsAt` в направлении из `sort`, затем по `id`.
- `MatchStatus` объявлен расширяемым: клиенты должны обрабатывать незнакомые значения.
- Рейтинг команды фиксируется при выходе матча из `upcoming` в любой статус, а не только в `live`.

### Что сделать клиентам

- Проверить, что незнакомое значение `status` не роняет приложение. Срок — до 2026-10-24.
- Для расписания передавать `sort=startsAt`.

## 1.0.0 — 2026-07-30

Первая версия: `GET /matches` с фильтрами по статусу и турниру, `GET /matches/{matchId}`.
